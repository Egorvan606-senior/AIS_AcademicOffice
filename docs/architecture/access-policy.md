# Политика доступа к будущему удалённому репозиторию

Владелец управляет доступом; разработчик работает в ветках задач;
рецензент проверяет изменения, читатель не изменяет код.
Для main предусматриваются Pull Request, одно одобрение и успешные проверки.
Это проект регламента, а не подтверждение включённой защиты на GitHub.

В истории запрещены реальные ведомости, персональные данные, ключи и пароли.
Для локальных данных используется private-data/, для секретов — .env.
.gitignore предотвращает обычное добавление новых файлов, но не удаляет уже
отслеживаемые данные и не запрещает git add -f. Перед коммитом проверяется индекс.
LFS хранит большие объекты отдельно, но не ограничивает круг читателей.
